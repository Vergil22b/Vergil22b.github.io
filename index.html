AML Alert Prioritization — Exploratory Data Analysis

Team CyberBaza · AML alert prioritization · hackathon entry

Public static report. Data: 20,000 alerts + ~10.0M transactions (train/test). Metric: ROC-AUC on eskalatsiya.

0. Approach

We model each alert as a single ML row aggregated from its transaction history, using only the leak-free window tranzaksiya_vaqti < signal_sanasi + 1 day (data contains 0 transactions after that window). EDA drove the design directly:
  • Amount statistics dominate signal (amount_min/abs/skew/per-type max) → rich amount+distribution features incl. quantiles and per-type shrinkage z-scores.
  • Same-day activity cluster (last 24 h, esp. last hour) → dedicated pre-alert window features (1h/6h/24h/3d/7d).
  • Train and test interleave in time (728 shared dates, not a future test period) → primary validation is 5-fold stratified random CV, with time-based holdouts as a robustness check.
  • Diverse model families, low OOF correlation → final rank-normalized equal-weight blend of XGBoost + LightGBM + CatBoost + LogisticRegression.

6. Features

Per-signal features (signal_id as key only, no target encoding):

  • basic — transaction_count, unique types/directions, active_days
  • amount — sum/mean/median/std/min/max, quantiles q10–q90, max/median, std/mean, skew
  • direction — kirim/chiqim counts, ratios, amount sums/means
  • type — per type (karta, bank_otkazmasi, naqd, xalqaro) count/ratio/amount sum/mean/max
  • temporal — first/last tx hour, activity span, mean/std hour, night & weekend ratios
  • pre-alert windows — counts (in/out/intl/cash/transfer) & amount in 1h/6h/24h/3d/7d before signal end
  • burst — tx/hour, tx/day, max tx in a day/hour, interarrival statistics
  • ratios — incoming/outgoing, intl/cash/transfer ratios
  • date — calendar components of signal date
  • advanced — quantile-bin histograms per type + shrinkage z-scores of per-type mean/std/count

7. Modeling

Validation: test and train are interleaved in time (728 shared dates) → primary scheme is 5-fold stratified random CV; time-based holdouts (valid ≥ 2026-01 / 2026-07) used as robustness check. Final pipeline = rank-normalized equal-weight blend of XGBoost + LightGBM + CatBoost + LogisticRegression on the selected 100-feature subset (deterministic selection by gain stability, seed 42). Production 5-fold OOF blend AUC 0.641; temporal holdouts blend 0.644 (≥2026-01) and 0.680 (≥2026-07). Iteration budgets come from OOS early stopping on a 12% stratified holdout, then a refit on 100% of train.

8. Conclusion

  • Target is imbalanced but stable: positive rate ≈ 17.2% (0.14–0.21 by month, no trend).
  • The main signal in the data is amount magnitude/spread (amount_min, amount_skew, per-type amount max/sum) and distributional deviation per type (z-scores) — these dominate gain importance.
  • Output flows (chiqim) and bank transfers (bank_otkazmasi) carry the strongest discrimination between escalated and dismissed alerts.
  • Temporal habits (std_hour, night/weekend ratio) and activity bursts (peak-to-mean) are secondary but consistent.
  • No future leakage: 0 transactions beyond the signal-day window in the source data.
  • Rank-average ensemble of 4 diverse models beats every single model (+0.006–0.008 AUC) and is stable across folds and time cuts.
